#Designเหมาะกับข้อดีข้อควรระวังScore
01VS Code Editor ทีมที่ code เป็นส่วนใหญ่ · เจอ file tree ทุกวัน รู้จักทันที · โชว์ progress ผ่าน file tree (✓ dots) ได้ตรง File tree แน่น · อาจไม่ scale ถ้าคอร์สเยอะ 8.5
02GitHub PR ทีมที่ทำ PR ทุกวัน · อารมณ์ "รอ merge" ปุ่ม "Merge & continue" เขียวๆ ดึงดูดสุด · reward ชัด บริบทค่อนข้าง GitHub เฉพาะ · non-dev อาจงง 9.0
03CI/CD Pipeline ทุกคน (ตี stage ให้เป็นบทเรียน) · animation flow เห็นทั้ง progress + current stage + log · เข้าใจง่ายที่สุด ต้องมี stage 4-6 พอดี · เกินไปแออัด 9.5
04cURL + JSON API-heavy team · SM ที่ debug API เป็นประจำ Playful · เห็น +50 XP highlighted ในผลลัพธ์ตรงๆ ข้อมูลเยอะ · อ่านตอนแรกๆ ต้อง scan 7.5
05Kanban Sprint PM/lead ที่ใช้ Linear/Jira · เห็น backlog รวม โชว์ทั้ง to-do + in-progress + done ในการ์ดเดียว · เห็นภาพรวม สูงกว่าอันอื่น 20px · ต้อง breakpoint แม่นๆ 8.0

แนะนำ: #3 CI/CD Pipeline เพราะ (1) animation ไหลจากซ้ายไปขวาสื่อ progress ตรงๆ (2) เห็น current stage + log line ที่กำลังทำ (3) ยืดหยุ่นสุด — เปลี่ยน stage เป็นอะไรก็ได้ รองลงมา #2 GitHub PR ที่ดึงดูดคลิกด้วยปุ่ม merge เขียวๆ
