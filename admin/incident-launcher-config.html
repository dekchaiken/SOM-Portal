Incident Launcher Config
ตั้งค่า Incident Cases · 9 Steps · Channels · Partners
กลับหน้า Launcher
ตั้งค่า Incident Launcher แต่ละ step ได้จากเมนูด้านซ้าย — step ไหนไม่มีการตั้งค่า จะแสดงว่า อัตโนมัติ
9 Steps
เพิ่มเติม
1
Open War Room
เปิด Google Meet + แจ้ง Chat ทันทีพร้อม link — ตั้งค่า URL ห้องและข้อความที่จะส่ง
War Room URL
ห้อง Google Meet ที่ใช้เป็น War Room หลัก
ถ้าว่าง — จะเปิด https://meet.google.com/new (link ใหม่ทุกครั้ง)  ·  อย่าใส่ Webhook URL ที่นี่
แจ้ง Google Chat พร้อม Meet Link
เมื่อกด "เปิดห้อง" ใน Launcher — ระบบส่งข้อความ + link ไปยัง channel ที่เลือกอัตโนมัติ
Ctrl+Click เลือกหลาย channel · ถ้าไม่เลือก = ไม่ส่ง Chat อัตโนมัติ
{meet_link} = URL ห้อง Meet ที่เปิด · ถ้าว่าง = ส่งแค่ Meet link
2
แจ้งช่องทาง
ตั้งค่าช่องทางแจ้ง incident — Google Chat, LINE Notify, DingTalk หรือ Manual Copy
Default Webhook (Legacy)
Webhook เดิมสำหรับ backward compat — แนะนำใช้ Channels ด้านล่างแทน
Notification Channels
แต่ละ channel มี template แยก · ปุ่มส่งและ Copy แสดงใน Launcher Step 2
Variables: ${severity}${title}${service} ${time}${reporter}${ticket} ${description}${resolved_time}

ยังไม่มี channel
เพิ่ม Channel
3
Create Jira Ticket
ตั้งค่า Jira issue type และ preset fields ที่แสดงใน Step 3 ของ Launcher
Jira Settings
ค่า default ที่ auto-fill ใน form ตอนเปิด Step 3
ปกติใช้ Monitoring (เหมือน Create SMC Ticket) · กด "โหลดจาก Jira" เพื่อดู types ทั้งหมด
Variables: {sev} = SEV 1/2/3  ·  {title} = ชื่อ incident  ·  {service} = service name
Variables: {service} {severity_label} {time} {description} {sev}
Default Values ของ Fields มาตรฐาน
ค่าที่ pre-select ไว้ล่วงหน้าเมื่อเปิด Step 3 — user ยังแก้ไขได้ก่อน submit
Multi-select: BU · Service · Channel เลือกได้หลายตัว · กด "โหลดจาก Jira" เพื่อดึง options จริง

กด "โหลดจาก Jira" เพื่อดู dropdown options จริงจาก Jira
Jira Preset Fields
ค่า default ที่แสดงเป็น input ใน Step 3 — user แก้ไขได้ก่อน submit · ดึง field list จาก Jira ได้เลย
ตัวอย่าง Field ID: customfield_17031 (TH Severity) · customfield_17026 (Fault Start) · ดู field ID ทั้งหมดได้จากปุ่ม "ดึงจาก Jira"
4
Email Partners
ตั้งค่า email template + partner groups ที่แสดงใน Step 4 ของ Launcher
Email Template
ใช้ {{ticket}}, {{title}}, {{service}}, {{date}}, {{time}}
Partner Groups
จัดกลุ่ม email ไว้ — กดปุ่ม group ใน Launcher เพื่อเพิ่ม email ทั้งกลุ่มทีเดียว

ยังไม่มี partner group
เพิ่ม Partner Group
รองรับ: plain email, Name <email>
5
Maintenance Actions
รายการ MA ที่ต้องทำระหว่าง incident — แสดงเป็น card ใน Step 5 ของ Launcher
MA Jobs
Jenkins, Rundeck, หรือ Manual · drag ลำดับได้
Jenkins: วาง Job URL แล้วกด Parse → ระบุ Server + Path อัตโนมัติ

ยังไม่มี MA job
เพิ่ม MA Job
เช่น /job/wallet-maintenance_login
6
MA Timestamp Log
บันทึกเวลา MA ทุก action อัตโนมัติ
Step นี้ทำงานอัตโนมัติ
ทุกครั้งที่กด Mark Done ใน Step 5 — ระบบจะบันทึกชื่อ MA + เวลาลง Timestamp Log ให้อัตโนมัติ
ไม่ต้องตั้งค่าเพิ่ม
7
Ticket → Investigating
ตั้งค่า Jira Transition ID ที่ใช้เปลี่ยนสถานะ ticket เป็น Investigating
Transition ID สำหรับ "Escalate as Incident" ใน Jira — ใช้ใน Launcher step Escalate
8
Service Performance
รายชื่อ services ที่แสดงใน Step 8 — embed service-performance.html แต่ละ service ไว้ใน Launcher
Services List
ค้นหาจาก inventory แล้วคลิกเพื่อเพิ่ม · ลำดับ = ลำดับที่แสดงใน Launcher Step 8
Services ที่เลือกแล้ว

ยังไม่มี service — ค้นหาด้านบน

Impact Summary
Query Prometheus 4 layers อัตโนมัติ
Step นี้ทำงานอัตโนมัติ

HTTP 5xx · Bank Errors · Business Impact · Pod Restarts
